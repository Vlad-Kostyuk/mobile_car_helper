## 1. Огляд продукту

### 1.1 Мета продукту
CarMaintenance — мобільний додаток для ведення технічного обслуговування автомобіля. Допомагає власникам автомобілів відстежувати виконані та заплановані роботи, отримувати нагадування про заміну деталей та мастил, а також зберігати повну історію обслуговування.

### 1.2 Цільова аудиторія
- Власники одного або кількох автомобілів
- Люди, які самостійно обслуговують авто або відвідують СТО
- Користувачі, яким важливо не пропустити регламентне ТО

### 1.3 Цінність продукту
- **Для користувача**: Ніколи не пропустити заміну масла, фільтрів, ременя ГРМ тощо
- **Для авто**: Подовжити термін служби завдяки своєчасному обслуговуванню
- **Для бюджету**: Уникати дорогостоящих поломок через нехтування ТО

## 3. Функціональні вимоги

### 3.1 Авторизація та аутентифікація

#### 3.1.1 Email/Password авторизація
- Реєстрація через email + пароль
- Вхід через email + пароль
- Відновлення паролю через email (reset link)
- Валідація email формату
- Мінімальна довжина паролю: 8 символів

#### 3.1.2 Google OAuth
- Кнопка "Sign in with Google"
- Використання Google Sign-In SDK для Flutter
- Auto-link акаунту якщо email збігається з email/password акаунтом

#### 3.1.3 Сесія
- Refresh token зберігається в secure storage (FlutterSecureStorage)
- Auto-refresh сесії
- Виходу з системи — очищення токенів

---

### 3.2 Onboarding та профіль

#### 3.2.1 Заповнення профілю (перший вхід)
Після першої авторизації відображається onboarding-флоу:
1. **Крок 1 — Особиста інформація:**
    - Ім'я (обов'язково)
    - Прізвище (опціонально)
    - Аватар (опціонально, вибір з галереї або камери)
2. **Крок 2 — Додавання першого автомобіля** (обов'язковий крок)

#### 3.2.2 Редагування профілю
- Зміна імені, прізвища, аватара
- Зміна email (з підтвердженням через поточний email)
- Зміна паролю
- Видалення акаунту (з підтвердженням та поясненням що станеться з даними)

---

### 3.3 Управління автомобілями

#### 3.3.1 Додавання автомобіля
Обов'язкові поля:
- Марка (бренд)
- Модель
- Рік випуску
- Поточний пробіг (км або милі)

Опціональні поля:
- VIN-код
- Назва / псевдонім (напр. "Моя ластівка")
- Фото автомобіля
- Номерний знак
- Тип пального (бензин, дизель, LPG, електро, гібрид)
- Об'єм двигуна

#### 3.3.2 Перемикання між автомобілями
- Бокове меню (Drawer) зі списком всіх авто
- Активний автомобіль виділений
- Кнопка "Додати автомобіль" в меню
- Редагування та видалення авто в меню

#### 3.3.3 Обмеження
- Безліміт на кількість автомобілів (можлива пагінація при >10)
- Видалення авто видаляє всі пов'язані роботи (з попередженням)

### 3.4 Роботи з технічного обслуговування

#### 3.4.1 Типи робіт

**Шаблонні роботи (System Templates):**
Попередньо налаштовані шаблони з рекомендованими інтервалами:

| Назва | Інтервал (км) | Інтервал (місяці) |
|-------|--------------|------------------|
| Заміна моторного масла | 10 000 | 12 |
| Заміна масляного фільтра | 10 000 | 12 |
| Заміна повітряного фільтра | 20 000 | 24 |
| Заміна паливного фільтра | 30 000 | 24 |
| Заміна ременя ГРМ | 60 000 | 48 |
| Заміна ланцюга ГРМ | 100 000 | — |
| Заміна свічок запалювання | 30 000 | 36 |
| Заміна охолоджуючої рідини | 60 000 | 48 |
| Заміна гальмівної рідини | 40 000 | 24 |
| Заміна гальмівних колодок (передні) | 40 000 | — |
| Заміна гальмівних колодок (задні) | 60 000 | — |
| Шиномонтаж / сезонна заміна шин | — | 6 |
| Перевірка та заміна акумулятора | — | 36 |
| Технічний огляд | — | 12 |
| ОСЦПВ / страховка | — | 12 |

**Кастомні роботи (User-Defined):**
- Назва роботи (вільний текст)
- Опис (опціонально)
- Інтервал по пробігу (км)
- Інтервал по часу (місяці/роки)
- Або обидва одночасно (що настане раніше)

#### 3.4.2 Запис виконаної роботи
Поля:
- Тип роботи (шаблон або кастом)
- Дата виконання
- Пробіг на момент виконання
- Де виконано (вдома / СТО — назва СТО)
- Вартість (опціонально)
- Запчастини (опціонально, список: назва + артикул + виробник)
- Нотатки (опціонально)
- Фото (опціонально, до 5 фото)
- Наступна дата / пробіг (автоматично або вручну)

#### 3.4.3 Планування майбутніх робіт
- На основі останнього запису + інтервалу автоматично розраховується наступне ТО
- Можливість вручну вказати дату та/або пробіг наступного ТО
- Статуси:
    - 🟢 OK (до ТО далеко)
    - 🟡 Скоро (< 20% до інтервалу)
    - 🔴 Прострочено (інтервал перевищено)

### 3.5 Головна сторінка / Dashboard

- Активний автомобіль з фото та основними даними
- Поточний пробіг (з можливістю оновити)
- Список найближчих робіт (топ-3 найбільш нагальних)
- Швидкий доступ: "Додати роботу", "Оновити пробіг"
- Підказки та поради (опціонально)

---

### 3.6 Сторінка робіт

#### 3.6.1 Перегляд
- Вкладки: "Заплановані" | "Виконані" | "Всі"
- Фільтр: конкретне авто або всі авто
- Сортування: за датою, за терміновістю, за типом
- Пошук по назві роботи

#### 3.6.2 Картка роботи
- Назва роботи
- Автомобіль (якщо режим "всі авто")
- Статус (кольорова мітка)
- Дата виконання / планова дата
- Пробіг виконання
- Коротка нотатка (preview)
- Кнопка "Позначити виконаним" для запланованих

---

### 3.7 Календар

- Місячний / тижневий вигляд
- Позначки на датах:
    - Синя крапка = виконана робота в цей день
    - Оранжева крапка = запланована робота
    - Червона крапка = прострочена робота
- Натискання на дату — список робіт цього дня
- Прокрутка по місяцях
- "Сьогодні" кнопка для швидкого повернення

---

### 3.8 Нотифікації

#### 3.8.1 Push-нотифікації
Тригери для нагадувань:
- За 30 днів до запланованої роботи
- За 7 днів до запланованої роботи
- За 1 день до запланованої роботи
- В день запланованої роботи
- За 500 км до порогу пробігу (якщо встановлено інтервал по пробігу)

Налаштування:
- Увімкнення/вимкнення всіх нотифікацій
- Налаштування кожного типу нагадування окремо
- Тихий режим (hours, наприклад 22:00–08:00)

#### 3.8.2 Сторінка нотифікацій (Inbox)
- Список всіх сповіщень
- Прочитані / непрочитані
- Видалення окремих або всіх
- Натискання → перехід до відповідної роботи

---

### 3.9 Офлайн-режим

#### 3.9.1 Вимоги
- Додаток повністю функціональний без інтернету
- Запис нових робіт офлайн
- Перегляд всіх даних офлайн
- Редагування та видалення офлайн

#### 3.9.2 Синхронізація
- Автоматична синхронізація при відновленні підключення
- Індикатор "Не синхронізовано" (кількість записів в черзі)
- Ручна синхронізація через кнопку
- Conflict resolution: "Остання запис виграє" (last-write-wins) з логуванням конфліктів
- Синхронізація у фоні (BackgroundSync)

#### 3.9.3 Локальне сховище
- SQLite через `drift` (Dart)
- Повна копія даних на пристрої
- Шифрування чутливих даних

---

### 3.10 Резервне копіювання та відновлення

- Експорт даних: JSON-файл або PDF звіт
- Імпорт при переустановці — автоматично після входу в акаунт
- Хмарне резервне копіювання (сервер Supabase / Firebase)
- Відновлення вибраного авто або всіх даних

## 4. Нефункціональні вимоги

### 4.1 Продуктивність
- Час запуску: < 2 секунди (холодний старт)
- Відклик UI: < 100 мс
- Синхронізація фонова: без блокування UI

### 4.2 Підтримка платформ
- iOS: 14.0+
- Android: 8.0+ (API 26+)

### 4.3 Безпека
- HTTPS для всіх запитів
- JWT токени з коротким терміном дії
- Refresh token rotation
- Sensitive дані в SecureStorage
- Опціональний PIN / Biometric lock

### 4.4 Доступність (A11y)
- Підтримка Dynamic Type (iOS) / font scaling (Android)
- Contrast ratio ≥ 4.5:1
- Screen reader сумісність

### 4.5 Локалізація
- Початкові мови: Українська, Англійська
- Налаштування одиниць: км або милі
- Формат дат: відповідно до локалі

## 5. Архітектура та технічний стек

### 5.1 Flutter архітектура
```
lib/
├── core/
│   ├── di/              # Dependency Injection (get_it + injectable)
│   ├── network/         # Dio + interceptors
│   ├── storage/         # Drift (SQLite) + SecureStorage
│   └── utils/
├── features/
│   ├── auth/            # Login, Register, OAuth
│   ├── vehicles/        # Car management
│   ├── maintenance/     # Works & records
│   ├── calendar/        # Calendar view
│   ├── notifications/   # Notifications
│   └── profile/         # User profile
└── shared/
    ├── widgets/
    └── theme/
```

### 5.2 State Management
- **Bloc / Cubit** (flutter_bloc)
- Repository pattern
- Local datasource + Remote datasource

### 5.3 Ключові пакети
| Пакет | Призначення |
|-------|------------|
| `flutter_bloc` | State management |
| `drift` | Local SQLite database |
| `dio` | HTTP client |
| `get_it` + `injectable` | Dependency injection |
| `go_router` | Navigation |
| `flutter_secure_storage` | Secure token storage |
| `google_sign_in` | Google OAuth |
| `firebase_messaging` | Push notifications |
| `table_calendar` | Calendar widget |
| `image_picker` | Photo upload |
| `connectivity_plus` | Network state |
| `flutter_local_notifications` | Local notifications |
| `intl` | Localization |

### 5.4 Backend
- **Auth**: Firebase Auth або Supabase Auth
- **Database**: PostgreSQL (Supabase) або Firebase Firestore
- **Storage**: Firebase Storage (фото)
- **Push**: Firebase Cloud Messaging (FCM)
